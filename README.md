# groq-srt

把中文音频/播客转成**能直接拖进剪映**的 SRT。用 Groq 的 Whisper 做识别，重点不在识别本身，而在识别之后那一段：气口对齐、断句、补漏。

```bash
python groq_srt.py podcast.m4a -o out.srt --key gsk_xxx
```

`GROQ_API_KEY` 也可以从环境变量读。依赖只有标准库 + 一个 ffmpeg。

## 它解决的是什么问题

Whisper 给的词级数据对中文并不友好，直接拿来切字幕会踩四个坑，这个脚本逐个填了：

**1. 词时间戳会倒挂，但不能按时间排序**

Whisper 的 `words` 是按**文本顺序**输出的，每个词的时间戳是**单独回归**的，相邻词经常差 0.2 秒就倒过来。`sorted(key=start)` 一排序，正确的字序就被搬了家：

```
原文：他此前创作的《大英博物馆世界简史》风靡全球
排序后：他此前创《作的大英 / 博物馆简世界》史风靡 / 全让球
```

音一个字都没错，纯粹是自己排坏的。实测 20 分钟音频有 **91 处**这种倒挂。所以这里只做**保序 + 时间轴单调化**，组内一律按字数铺开，完全不信任词时间戳。

**2. 整段跳读会被当成"识别差"**

长音频切块时，Whisper 偶尔会成段跳读：实测 20 分钟里第 3、4 块合起来少了约 300 字，某段 6 秒语音只识别出 1 个字。这种漏字断句和纠错都救不回来，因为文本里根本没有。

修法是用**语速密度当探针**：正常讲书 4~5 字/秒，低于全片中位数 55% 的语音段判为可疑，切出来单独重转写，补到更多字才替换。实测 8 个可疑段全部补回，其中 3 段从 0~2 字补到 44~91 字。

**3. 断句要跟着气口，不是跟着字数**

用 `ffmpeg silencedetect` 先估噪底、再找静音，取补集得到真实语音区间，把词重新钉到区间上，区间首词打 `brk` 标记 —— 这就是气口，断句优先在这里切。单条上限 11 字 / 4.5 秒，对齐剪映原生的分布。

**4. 切点不能劈开词**

中文没空格，按字数和标点找切点会切出「保｜命」「大英博｜物馆」。用 jieba 词典裁出 70860 个 2~4 字词（`zh_words.txt`），做**正向 + 逆向最大匹配取交集**消除歧义，所有切点只从可切位置选。词内切点从 20.6% 降到 1.3%。

## 效果

以剪映原生导出的字幕为基准（20 分钟讲书音频，原生 703 条 / 6872 字）：

| 版本 | 字数 | 字符一致率 | 差异片段 | 条数 | 0.2s 以下闪读 |
|---|---|---|---|---|---|
| 按时间排序 | 6851 | 96.00% | 212 | 717 | 0 |
| 只修字序 | 6557 | 92.42% | 106 | 701 | 0（但漏 294 字） |
| **修字序 + 补扫** | **6873** | **96.73%** | **113** | **719** | **0** |

均 9.6 字 / 2.13 秒，0 重叠、0 超长。剩下 113 处差异约一半是「四万年 vs 4万年」这类数字写法，真同音错字约 40~60 处（史诗**集**/级、**诗**人/石人、**旁观**/膀胱），这类只能靠 LLM 等长校对或人工过。

## 参数

| 参数 | 说明 |
|---|---|
| `--model` | 默认 `whisper-large-v3`，另有 turbo 档 |
| `--max-chars` / `--max-dur` | 单条上限，默认 11 字 / 4.5 秒 |
| `--overlap` | 切块重叠秒数，默认 3（交界处防漏词） |
| `--no-align` | 关掉 VAD 气口对齐 |
| `--dump-words` | 导出词级时间戳 JSON，便于离线调参 |
| `--dry-run` | 只转码不上传，验证 ffmpeg 和体积 |
| `--proxy` | 如 `socks5h://127.0.0.1:10808` |

## 不带 API 也能调的辅助脚本

跑一次真实音频要花额度，调断句参数时不必重跑：

| 脚本 | 用途 |
|---|---|
| `replay_words.py` | 用 `--dump-words` 的 JSON 离线重放，支持 `--max-chars` / `--sweep` |
| `xcheck.py` | 与剪映原生 SRT 做字符级比对，双行对照输出差异 |
| `density.py` | 按窗口统计字数密度，定位漏读区间 |
| `srtqc.py` | 时间轴体检：重叠、闪读、超长、条数分布 |
| `compare_order.py` | 量化"按时间排序"打乱了多少字序 |

## 局限

- 只针对中文调过，其他语种没验证。
- 识别质量取决于 Groq 的 Whisper，脚本只保证"不额外损失"。
- 无气口的长连续语流（「大英博物馆」一口气说完）仍可能切在语义不合适的位置。
